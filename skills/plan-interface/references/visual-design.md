# Visual organization and design direction

## R39 — Resolve the visual decisions that shape the task

Apply when composition, hierarchy, readability, density, consistency, or visual direction affects the requested result. For a local correction, resolve the affected relationships. For a broad redesign, choose a coherent treatment for representative full screens and significant states before implementation.

## Define the intended reading and action order

Choose what the person needs to notice, understand, compare, and do. Express those priorities through placement, relative scale, grouping, spacing, and contrast. Preserve the legibility of secondary information. Keep status and action meaning available beyond color, using the applicable platform and accessibility guidance.

State the important visual decisions at the detail the builder needs:

| Decision | Make concrete when relevant |
| --- | --- |
| Composition | Page regions, alignment, relationship of navigation to content, and where major actions live |
| Typography | Roles for headings, body, labels, metadata, and data; wrapping and readable treatment of long content |
| Density | Information needed together, useful comparison columns, spacing, and what can be deferred without obstructing work |
| Color and emphasis | Semantic roles for actions, states, selection, and surfaces; how emphasis follows task priority |
| Components | Repeated treatments, state distinctions, and deliberate exceptions to an existing system |
| Visual direction | Fit with supplied brand constraints, audience, content, references, and the intended tone |

Reuse compatible components and tokens. Where an existing system causes the problem, propose the necessary change and its affected uses. Keep a useful dense view when the task requires comparison; remove competing decoration or reorganize the composition before hiding required information. Do not prescribe one type scale, spacing system, card layout, or visual trend for every product.

## Explore a consequential alternative cheaply

When plausible directions differ materially, compare them using the same task, content, constraints, and significant states. A sketch of the main screen and a connected state may be enough to expose the tradeoff. Select a recommended direction and record why; no fixed number of alternatives is required.

Vary the relevant design decision: for example, a persistent contextual pane versus a separate detail destination when both could support the work. Palette changes alone do not explore that structural choice. Keep assumptions that would change the decision visible.

## Make the design inspectable

Use realistic content and representative full screens. Include the long or dense content, empty or error state, viewport, text expansion, or input condition that could invalidate the chosen layout. When visual composition is central and suitable tools are available, show a rendered mockup or prototype; identify any states it omits. Keep application changes within the authorized implementation stage.

Plan checks with concrete expectations: the specified action remains reachable, compared values stay available together, long labels fit or reveal their full content, component states remain distinguishable, and hierarchy follows the intended priority. Record the method and conditions. A visual review supports a design judgment; perceived trust, audience understanding, and conversion need appropriate observations.

## Professional basis and limits

- [Kelley Gordon, 5 Principles of Visual Design in UX](https://www.nngroup.com/articles/principles-visual-design/) supports using scale, hierarchy, balance, contrast, and grouping to organize a composition. Treat these as contextual expert guidance; avoid converting illustrative font counts into a universal rule.
- [Brad Frost, Interface Inventory](https://bradfrost.com/blog/post/interface-inventory/) supports comparing repeated component treatments and distinguishing deliberate variation from accidental inconsistency. Apply it to the relevant part of the interface.
- [Therese Fessenden, 3 Design Processes for High Usability](https://www.nngroup.com/articles/parallel-and-iterative-design/) explains why inexpensive alternative designs can broaden exploration before iteration. Agent comparison is an expert exercise; competitive or participant testing requires actual participants.
- The decision table, completion standard, and proposed checks above are this system's operational choices. They do not guarantee a measured usability improvement.

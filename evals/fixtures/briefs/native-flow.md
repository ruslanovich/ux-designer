# Site visit report

Design the same report task for a native iOS app and a native Android app. A technician opens an assigned visit, enters observations, attaches photos, marks equipment condition, and submits a report. The keyboard appears during long notes. Work may be interrupted or the connection may disappear. Drafts must survive leaving and returning. An explicit successful submission locks the report; a server conflict needs a recoverable state.

The user can enter from the visit list or a notification. Shared product logic and required information must stay consistent. Define meaningful platform-specific interaction decisions; no simulator, device, or app runtime is supplied with this brief.
